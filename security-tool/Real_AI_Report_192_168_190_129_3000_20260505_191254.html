דוח בדיקת חדירות אוטומטי - Advanced Security Scanner

יעד הבדיקה: http://192.168.190.129:3000

תקציר מנהלים

דוח זה מסכם את ממצאי בדיקת החדירות האוטומטית שבוצעה כחלק מפרויקט Advanced Security Scanner על היעד http://192.168.190.129:3000. התהליך כלל שלבי סריקה ראשוניים באמצעות כלים מובילים בתעשייה כגון ZAP, Nuclei ו-Dirb, שמטרתם הייתה לזהות נקודות תורפה וחולשות נפוצות. לאחר איסוף הממצאים הראשוניים, מערכת הניתוב מבוססת ה-AI של Advanced Security Scanner ניתחה את המידע וניתבה את נקודות התורפה שהתגלו לכלים ממוקדים לביצוע ניצול.

שלב הניצול (Exploitation Phase) הדגים חולשות אבטחה קריטיות, כולל דליפת נתונים רגישים משרת FTP חשוף, ואפשרות לקריאת קבצים שרירותית באמצעות עקיפת סיומת קובץ (Arbitrary File Read), שהובילה לחשיפת מידע קונפיגורציה פנימי. ממצאים אלו מצביעים על צורך מיידי בתיקון חולשות אבטחה מהותיות במערכת על מנת למנוע גישה בלתי מורשית ודליפת מידע.

ממצאי סריקה ראשונית (ZAP & Nuclei)

להלן טבלה המסכמת את ממצאי הסריקה הראשוניים שאותרו על ידי כלי הסריקה ZAP ו-Nuclei. ממצאים אלו שימשו בסיס לשלב הניצול האוטומטי.

ממצאי תקיפה מפורטים

שלב הניצול הדגים בהצלחה מספר חולשות קריטיות במערכת, המפורטות להלן.

חמור: דליפת נתונים קריטית משרת FTP חשוף

אותרה תקלת קונפיגורציה חמורה שאפשרה גישה ודליפת קבצים רגישים מתיקיית ה-FTP החשופה של השרת. חולשה זו נוצלה בהצלחה, וכתוצאה מכך נגנבו הקבצים הבאים:

  • /ftp/legal.md
  • /ftp/package.json.bak
  • /ftp/coupons_2013.md.bak
  • /ftp/acquisitions.md
  • /ftp/incident-support.kdbx אזהרה: קובץ זה הוא מסד נתונים של KeePass!
  • /ftp/admin-creds.txt.bak
אזהרה חמורה: גילוי הקובץ incident-support.kdbx, שהוא מסד נתונים של KeePass, מהווה סיכון אבטחתי קריטי. תוקפים יכולים להוריד ולפצח קובץ זה במצב לא מקוון כדי לגנוב את כל הסיסמאות הארגוניות והמפתחות הרגישים. זוהי דליפת מידע ברמה הגבוהה ביותר המחייבת טיפול מיידי.

חמור: קריאת קובץ שרירותית קריטית (LFI) - עקיפת סיומת קובץ

אותרה חולשה שאפשרה קריאת קבצים שרירותיים מהמערכת, תוך עקיפת מגבלות על סיומות קבצים. המתקפה נוצלה בהצלחה באמצעות שימוש ב"בייט ריק מורעל" (Poisoned Null Byte - %2500.md) כדי לגרום לשרת לפרש קובץ גיבוי כקובץ טקסט ולהציג את תוכנו. כתוצאה מכך, נחשף תוכן הקובץ package.json.bak, המכיל מידע קונפיגורציה פנימי:

{ "name": "Advanced Cyber", "version": "9.0.0", "description": "Educational vulnerable app — backup artifact for CTF lab only.", "dependencies": { "express": "^4.21.0" } }
אזהרה חמורה: חולשת קריאת קבצים שרירותית מאפשרת לתוקף לקרוא כל קובץ בשרת שזכויות הגישה שלו מאפשרות זאת. זה עלול להוביל לחשיפת קוד מקור, פרטי קונפיגורציה, אישורים, ולבסוף אף לביצוע קוד מרחוק (RCE).

מסקנות והמלצות

על בסיס הממצאים שפורטו לעיל, מומלץ ליישם את אמצעי האבטחה הבאים באופן מיידי:

אבטחת קונפיגורציית שרת ורכיבי ווב:

  • הגדרת כותרי אבטחה (Security Headers): יש להגדיר כותרות אבטחה קריטיות כגון Content-Security-Policy (CSP), X-Content-Type-Options, ו-X-Frame-Options (Anti-Clickjacking) כדי למנוע מתקפות נפוצות כמו XSS, Clickjacking והזרקת תוכן.
  • ביטול חשיפת ספריות (Directory Listing): ודא שחשיפת ספריות מושבתת בכל שרתי ה-Web. זה ימנע מתוקפים לגלוש בתיקיות השרת ולזהות קבצים רגישים.
  • הסרת מידע חשוף: סקור והסר כל מידע מיותר שחושף פרטים פנימיים של המערכת, כגון הערות קוד חשודות או חותמות זמן Unix, אשר עלולות לסייע לתוקפים.

אבטחת גישה לקבצים ונתונים:

  • אבטחת ספריית FTP: יש להסיר באופן מיידי את הגישה הציבורית לספריית ה-/ftp. במידה ונדרשת גישה, יש ליישם מנגנוני אימות והרשאות מחמירים (לדוגמה, SFTP עם אימות מבוסס מפתחות).
  • הסרת קבצים רגישים: יש להסיר לאלתר את כל הקבצים הרגישים שנגנבו (במיוחד incident-support.kdbx ו-admin-creds.txt.bak) מכל ספרייה נגישה לציבור. קבצים אלו מכילים מידע קריטי שעלול לסכן את כל המערכות הארגוניות.
  • ניהול קבצי גיבוי: קבצי גיבוי (כמו .bak) אינם צריכים להיות זמינים דרך ה-Web. יש לאחסן אותם במיקום מאובטח ולא נגיש, או למחוק אותם מיד לאחר השימוש.

הגנה מפני קריאת קבצים שרירותית:

  • אימות קלט קפדני: יש לבצע אימות קלט מחמיר עבור כל קלט שהמשתמש מספק, במיוחד בפרמטרים המשמשים לבניית נתיבי קבצים. יש להשתמש ברשימת מותרים (allow-list) עבור סיומות קבצים ונתיבים מורשים.
  • מניעת Null Byte Poisoning: ודא ששרת ה-Web וקוד היישום אינם מפרשים תווים "ריק מורעל" (Null Byte - %00 או %2500) כתווים מסימים במחרוזות. יש להשתמש בפונקציות בטוחות של טיפול בנתיבים.
  • מודל הרשאות: ודא שכל הקבצים והתיקיות בשרת מוגדרים עם הרשאות הגישה המינימליות ההכרחיות (Least Privilege Principle), כך שגם אם תוקף יצליח לקרוא קובץ, הוא לא יוכל לגשת לכלל המערכת.
הערה: בדיקות אלו בוצעו בסביבת בדיקה מבוקרת. מומלץ לבצע תיקונים בסביבת פיתוח/בדיקה ולאחר מכן לפרוס אותם באופן הדרגתי לסביבת ייצור. מומלץ לבצע בדיקות חדירות חוזרות לאחר יישום ההמלצות כדי לוודא את יעילות התיקונים.
