תקציר מנהלים

בדיקת חדירות אוטומטית בוצעה כנגד היישום בכתובת http://192.168.190.129:3000 במסגרת פרויקט "Advanced Cyber". תהליך הבדיקה כלל שני שלבים עיקריים:

  1. סריקה ראשונית: כללה שימוש בסורקי אבטחה מובילים כגון ZAP, Nuclei ו-Dirb לאיתור פגיעויות נפוצות, חשיפות מידע וספריות גלויות. סריקה זו סיפקה תמונת מצב מקיפה של חולשות פוטנציאליות.
  2. שלב הניצול: ממצאי הסריקה הועברו למנגנון ניתוב מבוסס AI, אשר הפנה את החולשות הרלוונטיות לכלי ניצול ייעודיים. במהלך שלב זה, בוצעו בהצלחה ניצולי SQL Injection שחשפו טבלאות מסד נתונים, פריצת חשבון מנהל מערכת שהובילה לגניבת סיסמה ואסימון JWT, דליפת נתונים קריטית מספריית FTP חשופה (כולל בסיס נתונים של KeePass), וחשיפת תוכן קבצים קריטיים באמצעות Local File Inclusion (LFI). בנוסף, נוצרו קישורי XSS לצורך בדיקות נוספות.

הדו"ח מפרט את הממצאים הטכניים משני השלבים ומספק המלצות לתיקון הפגיעויות שהתגלו.

מסקנות והמלצות

הבדיקה חשפה מספר פגיעויות קריטיות וגבוהות המצביעות על חולשות משמעותיות באבטחת היישום.

המלצות כלליות:

  • אימות קלט קפדני: יש ליישם אימות קלט קפדני וקידוד פלט בכל מקום בו נתונים המסופקים על ידי המשתמש מוצגים או מעובדים.
  • ניהול תצורה מאובטח: יש לוודא שספריות וקבצים רגישים אינם נגישים לציבור. כל קבצי הגיבוי והקונפיגורציה צריכים להיות מאוחסנים מחוץ ל-Web Root.
  • אבטחת חשבונות: יש לאכוף מדיניות סיסמאות חזקה, להטמיע אימות רב-שלבי (MFA) ולבצע הגבלת קצב (Rate Limiting) על ניסיונות התחברות.
  • ניהול סשנים: יש להשתמש בעוגיות מאובטחות (HTTPOnly, Secure, SameSite) לאחסון מזהי סשן ולהימנע מחשיפת מזהי סשן ב-URL.
  • כותרות אבטחה (Security Headers): יש להגדיר כותרות אבטחה חיוניות כגון Content-Security-Policy, X-Content-Type-Options ו-X-Frame-Options כדי להפחית סיכונים כמו XSS ו-Clickjacking.
  • ניהול טלאים ועדכונים: יש לוודא שכל רכיבי המערכת (מערכת הפעלה, שרת ווב, מסד נתונים, ספריות קוד) מעודכנים בגרסאותיהם האחרונות וכוללים את כל תיקוני האבטחה.
  • סקירות קוד ואבטחה: יש לבצע סקירות קוד אבטחתיות באופן קבוע, הן ידניות והן אוטומטיות, כדי לזהות ולתקן פגיעויות בשלבי הפיתוח המוקדמים.

המלצות ספציפיות:

  • לגבי הזרקת SQL:
    • השתמש בפקודות מוכנות (Prepared Statements) או שאילתות פרמטריות (Parameterized Queries) לכל האינטראקציות עם מסד הנתונים.
    • השתמש ב-ORM (Object-Relational Mapping) שמטפל באופן מובנה בהגנה מפני SQL Injection.
  • לגבי פריצת חשבון מנהל מערכת:
    • הטמע אימות דו-שלבי (2FA) לכל חשבונות המנהל.
    • הפעל מדיניות נעילת חשבון לאחר מספר מוגבל של ניסיונות התחברות כושלים.
    • בצע איפוס סיסמאות לחשבון המנהל שנפרץ וודא שהסיסמה החדשה חזקה ומורכבת.
    • ודא שאסימוני JWT מוחלפים בתדירות גבוהה, אינם ניתנים לגילוי בקלות, ומוגנים מפני התקפות XSS (למשל, באמצעות עוגיות HttpOnly).
  • לגבי דליפת נתונים מספריית FTP חשופה:
    • הסר את ספריית /ftp או הגבל את הגישה אליה באופן מיידי.
    • העבר את כל הקבצים הרגישים, ובפרט את קובץ ה-KeePass (incident-support.kdbx), למיקום מאובטח שאינו נגיש דרך הרשת.
    • יישם אימות והרשאות מתאימים לכל ספרייה או קובץ הנחשפים דרך שרת הווב.
  • לגבי קריאת קבצים שרירותית (LFI):
    • הגן על פונקציות קריאת קבצים באמצעות רשימת היתרים (Whitelist) של נתיבים וסוגי קבצים מורשים בלבד.
    • בטל את תמיכת השרת ב-Null Byte (%00) או בתווים דומים העשויים לעקוף אימות סיומות קבצים.
    • הימנע משמירת קבצי גיבוי (כגון .bak) בספריות נגישות לציבור.

טיפול מיידי בפגיעויות אלו קריטי להבטחת אבטחת היישום והגנה על נתוני המשתמשים.
