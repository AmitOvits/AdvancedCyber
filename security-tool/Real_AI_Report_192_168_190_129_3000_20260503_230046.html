דו"ח בדיקות חדירה אוטומטיות - CrossGuard-AI

יעד הבדיקה: http://192.168.190.129:3000

פרויקט: CrossGuard-AI

תאריך: 3 במאי 2026 (זמן הבדיקה)

תקציר מנהלים

דו"ח זה מפרט את ממצאי בדיקת חדירה אוטומטית שבוצעה כנגד היישום בכתובת http://192.168.190.129:3000, כחלק מפרויקט CrossGuard-AI.

התהליך האוטומטי כלל מספר שלבים:

  1. סריקה ראשונית: שימוש בכלי סריקה כגון ZAP (OWASP ZAP), Nuclei ו-Dirb לזיהוי נקודות תורפה וחשיפת משאבים.
  2. ניתוב חכם: מנוע AI ניתח את ממצאי הסריקה וניתב אותם לכלי ניצול ייעודיים.
  3. שלב הניצול (Exploitation): הפעלה של כלים כמו SQLMap (ניסיון כושל), מנגנון חטיפת מנהל מערכת מותאם אישית (Custom Admin Hijacker), כלי חדירת XSS (XSS Weaponizer), כלי לחילוץ קבצים מקומיים (LFI Extractor) וכלי לחילוץ נתונים מ-FTP (FTP Data Pillager) על בסיס הפגיעות שזוהו.

הבדיקה חשפה מספר פגיעויות קריטיות וברמת סיכון גבוהה, לרבות חשיפת ספריות וקבצים רגישים, ניצול פרצת קריאת קבצים שרירותית, פגיעות XSS ופריצה מלאה לחשבון מנהל מערכת, כולל גניבת טוקן JWT. פגיעויות אלו מהוות סיכון משמעותי לנתוני המערכת ולשלמותה.

ממצאי סריקה ראשונית (ZAP & Nuclei)

להלן סיכום הפגיעויות שזוהו בשלב הסריקה הראשוני על ידי כלי ZAP ו-Nuclei:

ממצאי תקיפה מפורטים (Exploitation Phase)

שלב הניצול חשף מספר פגיעויות קריטיות שהובילו לפריצה למערכת ולדליפת נתונים.

1. חשיפת ספריות וקבצים רגישים (Dirb Discovery)

הסורק Dirb זיהה מספר ספריות וקבצים נגישים בשרת, חלקם בעלי פוטנציאל לחשיפת מידע או ניצול נוסף:

  • /assets (קוד: 301)
  • /ftp (קוד: 200) - ספריית FTP חשופה.
  • /media (קוד: 301)
  • /profile (קוד: 500)
  • /promotion (קוד: 200)
  • /redirect (קוד: 500)
  • /robots.txt (קוד: 200)
  • /video (קוד: 200)
  • /Video (קוד: 200)

הנגישות לספריית /ftp הובילה לדליפת נתונים קריטית, כפי שיפורט בהמשך.

2. ניצול הזרקת SQL (SQL Injection Attempt)

כלי ZAP זיהה פגיעות SQL Injection אחת ברמת סיכון גבוהה. מנוע ה-AI ניסה לנתב זאת לכלי SQLMap, אך ניסיון הניצול לא צלח עקב שגיאה בתצורה או בהפעלה של SQLMap (TypeError: run_remote_sqlmap() missing 1 required positional argument: 'kali_ip').

אף על פי כשל הניצול האוטומטי, קיום הפגיעות כפי שזוהה על ידי ZAP מהווה סיכון משמעותי ומחייב טיפול מיידי.

4. דליפת נתונים קריטית דרך ספריית FTP חשופה (Exposed Data Leakage)

הנגישות לספריית /ftp אפשרה חילוץ קבצים רגישים מהשרת:

  • acquisitions.md
  • incident-support.kdbx (קובץ KeePass - מכיל סיסמאות תאגידיות!)
  • announcement_encrypted.md
  • package.json.bak
  • package-lock.json.bak
  • coupons_2013.md.bak
  • legal.md

זיהוי קובץ incident-support.kdbx הוא קריטי ביותר, מכיוון שהוא יכול להכיל את כל הסיסמאות הארגוניות, וניתן לפצח אותו במצב לא מקוון. זוהי דליפת מידע חמורה ביותר.

5. הזרקת Cross-Site Scripting (XSS)

כלי ה-XSS Weaponizer יצר 20 לינקים זדוניים, המעידים על פגיעות פוטנציאלית ל-DOM-based XSS בפרמטר החיפוש. להלן מספר דוגמאות ל-payloads שנוצרו:

  • <script>alert("XSS_1_Classic")</script>
  • <img src="x" onerror="alert('XSS_2_Image')">
  • <svg onload="alert('XSS_3_SVG')">
  • "><script>alert("XSS_5_BreakOut")</script>
  • javascript://%250Aalert("XSS_19_ProtocolBypass")

פגיעות XSS מאפשרת לתוקפים להריץ קוד בצד הלקוח בדפדפן של המשתמשים, מה שעלול להוביל לגניבת סשנים, הסטת משתמשים או השחתת מידע.

6. קריאת קבצים שרירותית (Arbitrary File Read / LFI)

הושגה עקיפה מוצלחת של הגבלות סיומת קבצים באמצעות Poisoned Null Byte (%2500.md), מה שאפשר קריאת קבצים שרירותית מהמערכת.

קריאת קבצים שרירותית מאפשרת לתוקף לגשת לקונפיגורציות מערכת, קוד מקור, קבצי לוג ומידע רגיש נוסף, ובכך להשיג הבנה מעמיקה יותר של המערכת ולחפש נקודות תורפה נוספות.

מסקנות והמלצות

הבדיקה חשפה פגיעויות חמורות המאפשרות פריצה למערכת, גניבת נתונים ושליטה מלאה. מומלץ לנקוט בצעדים הבאים באופן מיידי:

1. הגנה מפני הזרקת SQL

  • ולידציה של קלט: יש לוודא שכל קלט מהמשתמשים עובר ולידציה יסודית בצד השרת.
  • שאילתות פרמטריות/Prepared Statements: יש להשתמש תמיד בשאילתות פרמטריות (Parameterized Queries) או ב-Prepared Statements בעת גישה למסד הנתונים כדי למנוע הזרקת SQL.
  • ORM (Object-Relational Mapping): שקול שימוש בפריימוורקים של ORM המספקים הגנה מובנית מפני הזרקת SQL.

2. אבטחת חשבונות והרשאות

  • מדיניות סיסמאות חזקה: לאכוף מדיניות סיסמאות חזקה הכוללת אורך מינימלי, תווים מיוחדים ושינוי תקופתי.
  • אימות רב-שלבי (MFA): הטמעת אימות רב-שלבי (Multi-Factor Authentication) עבור חשבונות מנהל וחשבונות רגישים אחרים.
  • בקרת גישה: ליישם עקרון של הרשאות מינימליות (Least Privilege) לכל המשתמשים והשירותים.
  • הגבלת קצב (Rate Limiting): להטמיע הגבלת קצב על ניסיונות התחברות כדי למנוע התקפות Brute-Force.
  • אבטחת טוקני JWT: לוודא שטוקני JWT מאוחסנים בצורה מאובטחת, בעלי זמן חיים קצר ומוחלפים בעת התנתקות. להשתמש באלגוריתמי חתימה חזקים ולבצע ולידציה מלאה של הטוקנים בצד השרת.

3. הגנה מפני Cross-Site Scripting (XSS)

  • קידוד פלט (Output Encoding): יש לקדד תמיד את כל הקלט המוצג למשתמש (HTML Encoding, URL Encoding, JavaScript Encoding) כדי למנוע הרצת קוד זדוני.
  • מדיניות אבטחת תוכן (CSP - Content Security Policy): ליישם כותרת CSP חזקה כדי להגביל את המקורות מהם דפדפנים יכולים לטעון משאבים.
  • ולידציה של קלט: לבצע ולידציה של כל הקלט מהמשתמשים, במיוחד במקומות בהם קיים חשש ל-XSS.
  • שימוש בפריימוורקים מאובטחים: להשתמש בפריימוורקים המציעים הגנה מובנית מפני XSS.

4. אבטחת קבצים וספריות

  • הגבלת גישה לספריות: לבטל את הגישה הציבורית לספריות רגישות כמו /ftp. יש לוודא שכל ספרייה שאינה מיועדת לגישה ציבורית מוגנת באמצעות אימות והרשאות מתאימות.
  • הסרת קבצים רגישים: יש להסיר באופן מיידי קבצים רגישים כמו incident-support.kdbx, package.json.bak, coupons_2013.md.bak, וכל קובץ גיבוי או קובץ המכיל מידע פנימי מהסביבה הנגישה לציבור.
  • הגבלות העלאת קבצים: אם היישום מאפשר העלאת קבצים, יש לוודא ולידציה קפדנית של סוג הקובץ, גודלו ותוכנו. אין לסמוך על סיומת הקובץ בלבד.
  • תיקון פגיעות LFI: יש לוודא שכל פונקציית קריאת קבצים (כמו LFI) מאמתת היטב את נתיבי הקבצים ומונעת יציאה מחוץ לספריות מורשות (Path Traversal). להימנע משימוש בת תו נול (Null Byte) בבדיקת סיומות קבצים.

5. אבטחת כותרות HTTP

  • הגדרת כותרות אבטחה: לוודא שכל כותרות האבטחה החשובות מוגדרות כראוי:
    • Content-Security-Policy
    • X-Content-Type-Options: nosniff
    • X-Frame-Options: DENY (מניעת Clickjacking)
    • Strict-Transport-Security (לפורט 443 במידה וקיים TLS)

6. תחזוקה כללית

  • עדכוני תוכנה: לוודא שכל התוכנות, פריימוורקים וספריות צד שלישי מעודכנים באופן שוטף לגרסאות האחרונות.
  • בדיקות אבטחה תקופתיות: לבצע בדיקות חדירה ידניות ואוטומטיות באופן קבוע.
  • Web Application Firewall (WAF): שקול הטמעת WAF מול היישום להגנה מפני התקפות נפוצות.

טיפול יסודי ומהיר בפגיעויות אלו קריטי להבטחת אבטחת המערכת והגנה על נתוני המשתמשים והארגון.
